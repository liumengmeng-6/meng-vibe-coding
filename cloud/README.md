## ⚠️ 这个页面长成业务页的样子，但数据全是假的

`mock/index.html` 上展示的**行程、花费、清单**（①②③④ 四块）**全是写死的假数据**（页面顶部有醒目标注）。

只有**最底下那块「⑤ 后端连通性」是真的** —— 它真的去请求云函数。

**为什么做成这样**：这个页面的作用是**验证部署链路**（前端能不能上公网、别人能不能打开），
所以把它做成"业务页的样子"，演示的时候能一眼看出"上线之后大概长什么样"；
但它**不做真实计算** —— 真算的那套逻辑在主产品里，搬过来就等于把主产品复制一份，没必要。

- 想用真产品 → 打开仓库根目录的 `index.html`（**双击就行，不用联网**）
- 想看部署效果 / 测后端 → 用这个演示页

## 怎么用

### 打开演示页

**线上地址**（需联网）：

```
https://travel-planner-d4g8o6mee9d231c64-1499365786.tcloudbaseapp.com/backend-test/
```

**本地打开**：双击 `cloud/mock/index.html`
（页面上的假数据能看，但底部测后端那块要联网才有效）。

### 测后端连通性

拉到页面最下面「⑤ 后端连通性」区块：

1. 在输入框填云函数地址：
```
https://travel-planner-d4g8o6mee9d231c64.service.tcloudbase.com/api/health
```
2. 点「测试连通性」
3. 🟢 **绿色 + JSON** → 通了

> **地址会被记住**（存在浏览器本地），下次打开自动带出来，不用重填。

### 更直接的测法（不依赖浏览器跨域）

在浏览器地址栏**直接粘贴云函数地址**回车，或在命令行跑：

```bash
curl https://travel-planner-d4g8o6mee9d231c64.service.tcloudbase.com/api/health
```

**能看到 JSON 就说明后端通了。** 这两种方式不受跨域限制，是排查问题的第一选择。
